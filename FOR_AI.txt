=== РОЛЬ И НАЧАЛО РАБОТЫ ===

Ты продолжаешь разработку Vision Mod вместе с его владельцем. Пользователь
пишет по-русски, иногда коротко и разговорно. Разберись в фактическом
поведении проекта, учитывай историю ниже и отвечай по-русски. Выполняй
следующую задачу пользователя с правками в репозитории и проверками.

Начни с git status --short --branch, git log -8 --oneline и README.md.
Сверь рабочую копию, ветку и последние изменения. Если тебе сначала
поручили прочитать код, изучи соответствующую версию и дождись задачи.
«Продолжай» или «=» в ходе работы означает продолжить активную задачу
с текущего состояния. Уточнения владельца важнее старой памятки. Перечень
35 функций ниже по ссылкам отражает долгосрочный замысел проекта.

Работай самостоятельно. Разбирай ошибки по исходникам, логам и повторяемым
проверкам. Прими обратимые технические решения сам. Спрашивай, когда без
ответа нельзя понять требование или продолжить работу. Сохраняй чужие
изменения в рабочей копии. Правь нужные модули и доводи задачу до результата,
включая сборку JAR, если поменялось поведение мода. Если сборка или тест
не прошли, разберись с причиной и повтори проверку. В ответе дай результат,
путь в игровом меню, если он нужен, и сборку либо конкретный оставшийся
блокер. Для длинной задачи сообщай о существенных находках по ходу работы.

=== РЕПОЗИТОРИЙ И ТЕХНОЛОГИИ ===

Основной репозиторий https://github.com/De1po3oN/VisionMod-2.0.0.
Его прежнее имя и имя рабочей папки в Cloud — VisionMod-1.0.0. Другие
VisionMod-0.x, VisionMod-Standalone и VisionMod в /workspace содержат
исторические версии. Бери свежие исходники из VisionMod-1.0.0, если
пользователь не назвал другую версию.

Текущая ветка разработки — codex/visual-refresh. Проверенные изменения
публиковались в ней. Для main отдельного указания о слиянии пока не было.
codex/visual-evidence служит для выходных файлов CI. qa/sacred-war и
qa/item-render-hooks — отдельные экспериментальные ветки и рабочие копии.
Папки /workspace/artifacts и /tmp зависят от среды, поэтому в ссылках на
готовые сборки используй точный опубликованный коммит.

Версия мода 2.0.0 Open Beta. Minecraft Java 1.21.11, JDK 21, Gradle 9.7.1,
Fabric Loom 1.17.20, Fabric Loader 0.19.3+, Fabric API 0.141.6+1.21.11.
Маппинги официальные Mojang. build.gradle собирает
build/libs/visionmod-2.0.0.jar и вкладывает JEI 27.54.0.113 с MezzConfig
0.6.11. Оба вложения нужны для совместимости с текущим JEI. Fabric API
остаётся обычной зависимостью. Клиентские модули регистрируются в
VisionModClient, общий вход VisionMod отвечает за регистрацию обмена V.
Один JAR поддерживает установку на клиент и запуск выделенного сервера.

=== ЧТО ВЛАДЕЛЕЦ СЧИТАЕТ ХОРОШИМ РЕЗУЛЬТАТОМ ===

- Чистый Fabric-мод. World Lyrics получает данные медиасессии из самой
  игры через системный интерфейс. Браузерное расширение, локальный мост
  и обязательный отдельный сервис отменены.
- Аккуратный GUI со своим дизайном, понятными настройками, плавными
  переходами и сохранением рабочего состояния. ТГК @cocok_ali и сервер
  mc.showtime.su должны оставаться в интерфейсе. Fading Visuals / Fading
  Light использовался как функциональный и визуальный ориентир. Ресурсы
  и код закрытого мода не входят в Vision Mod. Шрифт Inter из открытого
  источника, лицензия и сведения есть в THIRD_PARTY_NOTICES.md.
- Реальная работа функции через обычное управление, а для визуала ещё и
  результат в кадре. Удачная компиляция подтверждает сборку. Smoke
  подтверждает запуск и свои проверки. Клиентский GameTest проверяет
  конкретный сценарий в Minecraft. Про FPS можно говорить после замеров.
- Пользователь хочет высокий и стабильный FPS, особенно на людном спавне.
  Ограничивай работу на тик и кадр, сохраняй обратимость видеонастроек.
  Сравнивай FPS и 1% low в одинаковой сцене и конфигурации; для отчёта
  подойдут три прогона по 60 секунд, средний FPS и время кадра.
- Для показа игрокам делай реальные кадры из Minecraft. Прикладывай
  доступный файл или прямую ссылку на PNG. Для каждого результата
  различай тестовое воспроизведение и живой пользовательский сценарий.

=== КАРТА КОДА И ТЕКУЩЕЕ ПОВЕДЕНИЕ ===

GUI, настройки и ввод
- Right Shift открывает VisionDashboardScreen через VisionMenuSession.
  Память раздела, страницы, поиска и дочернего экрана живёт в пределах
  запущенного Minecraft. Right Shift закрывает меню в игру и возвращает
  туда же. Escape из настроек возвращает в родительский экран.
- DashboardLayout и PanelLayout задают размеры и области клика.
  VisionGuiTheme и VisionFonts оформляют меню; VisionHudTheme оформляет
  HUD. Значения ТГК и сервера лежат в VisionMenuTheme, общая подпись
  рисуется через VisionGuiTheme.branding. ЛКМ по переключателю, ПКМ
  открывает детали, СКМ назначает бинд. Проверяй компактный и широкий GUI.
- VisionHotkeys, VisionAppearance, VisionProfiles и локальные properties
  хранят бинды, внешний вид и значения. Сохраняй существующие ID и чтение
  старых конфигов. End — глобальный OFF с восстановлением параметров FPS
  Boost. В открытом чате HUD двигается ЛКМ, позиция сбрасывается ПКМ.
- Free Look работает на удержании Left Alt. Мышь вращает камеру, yaw/pitch
  игрока сохраняются. Отпускание сразу возвращает прежнюю перспективу,
  F5 отменяет орбиту в пользу ванильного вида. FreeLookCameraMixin
  оборачивает оба вызова Camera.setRotation в Camera.setup. Ordinal 0
  относится только к одной ветке, обычная камера использует другую.
  Смотри также FreeLookMouseMixin и VisionControlsGameTest.
- SmoothHotbarMixin и HotbarTween плавно передвигают выделение примерно за
  140 мс. Выбранный предмет меняется сразу. Сохраняй управление цифрами,
  колесом и выключение анимации.
- Fast Scroller (VisionFastScroller, FastScrollGesture,
  ContainerScreenAccess) использует ванильный QUICK_MOVE. Shift + колесо
  над слотом или Shift + ЛКМ с ведением по слотам в обычном инвентаре и
  контейнере. Дедупликация слотов на один жест, проверка взятого стека.
  MouseHandler.isLeftPressed относится к игровому вводу; GUI использует
  свои события press/release. Проверяй серверные остатки, модификаторы,
  переполненный контейнер и выключение. Креативный каталог вне охвата.

Мир, видимость и боевые эффекты
- VisionWorldEffects рисует Target ESP, Trails, Jump Circles, China Hat.
  VisionFeaturePack держит Target HUD, дистанцию, броню, индикацию TNT и
  стрел, Hit Pulse. VisionCombatTracker отслеживает реакцию сущности на
  собственную атаку клиента. «Target down» означает наблюдение гибели
  цели после удара. Серверную атрибуцию убийства мод не получает.
- Последний фикс инвиза проверяет LivingEntity.isInvisible() для цели
  под прицелом и сохранённой цели в HUD. В момент смены видимости фильтр
  действует при отрисовке. Friend Zone и боевые эффекты также проверяют
  невидимость. При добавлении нового эффекта, связанного с чужой
  сущностью, проверь отображение и уже активный эффект после её ухода в
  инвиз. По умолчанию сохраняется ванильное поведение TAB.
- Визуал → Скрыть ники и бирки выключает мировые подписи игроков и
  сущностей через HideEntityNameTagMixin и VisionPlayerBadgeMixin.
  Настройка сохраняется в Appearance и профилях. Проверки в
  VisionNameTagGameTest.
- Утилиты → Friend Zone → Настроить открывает список других видимых
  игроков до 48 блоков и вкладку сохранённых друзей. Добавление из строки
  и по нику, удаление офлайн, текущая вкладка при возврате. Поиск рядом
  общий для GUI и HUD, см. VisionExtendedFeatures.nearbyPlayers и
  VisionFriendZoneScreen. Старое имя Social Radar ищется как псевдоним.
- Метка V рядом с ником — VisionPresence, VisionPresenceClient и mixins.
  Для чужих клиентов нужен тот же JAR на Fabric-сервере с Fabric API.
  Сервер берёт UUID из соединения. Без поддержки видна собственная
  метка в TAB. Включение, отзыв и очистка при disconnect входят в
  игровой тест; обмен между двумя отдельными клиентами не проверялся.
- Ore Highlight → Настроить → Радиус. Макс. 64 блока от игрока по каждой
  горизонтальной оси, вертикаль до ±6 блоков. Радиус хранится в
  VisionPerformance, профилях и общем переключателе VisionHotkeys.
  OreHighlight индексирует только загруженные секции чанков. Palettes
  позволяют пропускать секции без поддерживаемых руд. Кэш пополняется
  по секциям на ходу; ограничение выбирает ближайшие открытые руды.
  Контур слегка вынесен за поверхность блока, использует глубину мира.
  Адаптивный режим ограничивает работу и количество контуров, сохраняя
  выбранный радиус. Переключение пресета выставляет значение пресета.
- Item Physics (VisionItemPhysicsMixin) гасит ванильное вращение
  выпавшей модели и укладывает её при контакте с землёй. Плоские
  предметы ложатся небольшой стопкой, толстые 3D-модели раскладываются
  на уровне пола. В полёте остаётся анимация. При OFF возвращается
  ванильный вид. Не меняй
  положение ItemEntity и механику подбора ради визуальной правки.
- Эффекты Spear используют реальный MultiPlayerGameMode.piercingAttack
  и отложенный импульс Lunge, который отслеживает SpearLungeTrigger.
  Pierce приходит из ClientboundDamageEventPacket с DamageTypes.SPEAR
  и sourceCauseId локального игрока. Проверено настоящим ударом и Lunge III,
  обычная ходьба с копьём эффекта не вызывает. Клиентская геометрия
  VisionSpearEffects не меняет механику копья.
- VisionPetRenderer + PetMotion — локальный 3D-питомец. Плавное движение
  по сторонам с задержкой относительно камеры, мягкий возврат,
  сглаженная высота в прыжке. Учитывай самый короткий путь через ±180°,
  телепорт, смену игрока/мира и F5. Лишнюю цветную коробку пользователь
  заметил в F5. Исправлены реальные причины рядом с камерой: пример
  Custom Models теперь использует yaw корпуса и расположен на спине,
  декорации скрываются при близкой камере. Точный объект по одному
  описанию не идентифицирован. В буферах мира держи согласованный
  материал и баланс pose stack, чтобы не вернуть сбой «Not building».
- FPS Boost (VisionRenderBoost), бюджеты VisionPerformance, кэш
  VisionSignOptimizer, фильтр частиц работают отдельно от GUI.
  Сохраняй явное включение Air Hearts/Snowflakes даже в MAX FPS и
  при фильтрации обычных частиц. Проверяй восстановление сохранённых
  видеонастроек. Изменения рендера клиента сами по себе не меняют TPS.

World Lyrics и музыка
- Требование владельца: видны слова песни в темп с музыкой как отдельная
  2D-плоскость в мире перед персонажем, видимая из камеры. VisionWorldLyrics рисует
  её в END_MAIN с отдельным Font buffer, обычной глубиной и читаемым
  текстом с обеих сторон. WorldLyricMotion берёт позицию и yaw игрока
  с плавным следованием. Free Look и F5 меняют точку наблюдения;
  текст сохраняет мировую позицию, меняет перспективный размер,
  перекрывается стеной. Привязка anchor к camera.position, SEE_THROUGH,
  отрицательный масштаб X и дубликат в HUD приносили регрессии.
- SystemMediaReader и SystemMediaTrack читают Windows Media Control
  через встроенный PowerShell или Linux MPRIS через gdbus. Медиаплеер
  передаёт позицию, паузу, скорость и длительность при наличии. macOS
  пока без автоматического чтения. VisionLyricsSource и LrcTimeline
  используют известную позицию, уважают паузу, перемотку и пустые
  интервалы. При отсутствии музыки и локальных строк плоскость пуста.
- VisionLyricsLookup + LyricsSearch проверяют название, артистов, версию
  и длительность. Источники: LRCLIB, Яндекс Музыка с личным доступом и
  запасной lyrics.ovh. Важны таймкоды конкретной записи. При смене
  композиции отменяй устаревшие запросы. Название песни показывается
  в статусе настроек, в мире выводятся слова.
- В настройках есть импорт LRC/обычного текста и ручная позиция,
  пауза, синхронизация с проигрывателем, листание обычных строк. Это
  запасной пользовательский режим. Источники могут не иметь текста,
  таймкодов или нужной записи. Не придумывай время строк и не объявляй
  проверенным покрытие всех песен. Свои строки и локальный LRC
  необязательны для автоматического режима.
- Яндекс: VisionYandexScreen, YandexMusicAccess, YandexLyricsClient.
  Пользователь вводит свой OAuth в игре. Токен маскируется, нужен
  только в памяти текущего запуска, не записывается в профили и не
  уходит на сторонний URL скачивания текста. Не проси присылать его
  в чат и не печатай в логах. HTTP-fixture проверяет работу протокола;
  настоящий вход и закрытые тексты Яндекса не подтверждены. Публичный
  запрос из CI возвращал HTTP 451, у клиента есть статус для этого.
- «Священная война» — пользователь просил показ с живым проигрыванием
  и автоматической загрузкой. В qa/sacred-war проводились отдельные
  попытки подбора записи и таймкодов. Успешный кадр с подтверждённым
  совпадением записи не получен. Если к задаче вернутся, проверить
  легально доступную конкретную запись, её медиасессию и реальные
  совпадающие таймкоды. Вставленный текст не выполнит этот запрос.

=== ПРОВЕРКА И ВЫПУСК ===

Команды из корня репозитория

  bash tests/run-core.sh
  gradle build --no-daemon --max-workers=2
  gradle -PvisualGameTest gametestClasses inspectMinecraftHooks downloadAssets --no-daemon --max-workers=2
  xvfb-run -a gradle -PvisualGameTest runClientGameTest --no-daemon --max-workers=2
  gradle -PvisualGameTest verifyLiveLyrics --no-daemon --max-workers=2

Для клиента Minecraft без дисплея бери настройки Xvfb/Mesa из
.github/workflows/world-visual.yml. Изолированный Linux MPRIS проверяет
bash tests/run-mpris.sh с gdbus, dbus-run-session и dbus-next. Нативный
Windows API проверяет .github/workflows/native-media.yml. В прошлой
облачной среде не было Gradle и полного JDK. Проверяй наличие локальных
инструментов; при отсутствии используй доступный CI и его логи.

Тесты живого клиента лежат в src/gametest/java/com/visionmod.
VisualWorldGameTest оркестрирует общий прогон. InspectMinecraftHooks
показывает реальные вызовы Minecraft, полезен при проблемах с mixin.
Компиляция Java сама по себе не проверяет точки инъекций. При визуальной
регрессии проверяй пиксели framebuffer и клики/движение в реальном мире.
Для парных сценариев проверь OFF, смену состояния и возврат к обычному
поведению. Не заменяй всю игровую проверку фактом вызова renderer.

Рабочие workflows — build.yml, client-smoke.yml, world-visual.yml.
Стартовый smoke проверяет 55 переключателей и кадры редакторов.
world-visual запускает реальный интегрированный мир, публичный lookup
и выделенный сервер. LiveLyricsSmoke подтверждает доступность обычного
публичного запроса LRCLIB, отдельно от настоящего аудио игрока.
tests/publish-evidence.sh публикует build/, smoke/ и world/ в
codex/visual-evidence. В каждом каталоге есть source.json с code SHA и
Actions run. Сверь его с твоим коммитом перед тем, как отправлять JAR,
лог или кадр. Выходные папки обновляются независимо, в отчёте лучше
ссылаться на неизменяемый evidence SHA.
